## 정의

HTTP(Hypertext Transfer Protocol)는 클라이언트와 서버 간 통신을 위한 통신 규칙 세트, 프로토콜이다. 또한, OSI(Open Systems Interconnection) 네트워크 통신 모델의 애플리케이션 계층 프로토콜이다.

## HTTP/0.9

요청은 단일 라인으로 구성되며 GET 메소드가 유일했다.

```bash
// request
GET /mypage.html

// response
<html>
  A very simple HTML page
</html>
```

HTML 파일만 정송될 수 있어 HTTP 헤더가 없었다. 또한, 상태 혹은 오류 코드도 없었다. 문제가 발생할 경우 특정 HTML 파일이 만들어지고 사람이 처리할 수 있도록 했다.

## HTTP/1.0

다양한 프로토콜이 생기는 상황에서 이를 하나로 정리하기 위해 나온 HTTP 버전이다.

- 요청 메시지와 응답 메시지에 **헤더**가 추가됐다.
- 헤더에는 메시지의 정보를 담고 있으며 버전 정보, 상태 코드 그리고 문서타입을 헤더를 통해 확인할 수 있다.
- 하지만 해당 HTTP 버전은 공식 표준은 아니였다.

```bash
// request
GET /mypage.html HTTP/1.0
User-Agent: NCSA_Mosaic/2.0 (Windows 3.1)

// response
200 OK
Date: Tue, 15 Nov 1994 08:12:31 GMT
Server: CERN/3.0 libwww/2.17
Content-Type: text/html
<HTML>
A page with an image
  <IMG SRC="/myimage.gif">
</HTML>
```

## HTTP/1.1

HTTP의 첫 번째 표준화 버전이다.

- 1.0 버전에서는 요청을 보낼 때 마다 새로운 연결을 맺고 요청이 끝나면 연결을 끊었다.
- 똑같은 컴퓨터와 계속 통신을 하기위해서는 연결을 맺고 끊는 작업을 여러번 해야한다.
- 이를 개선하기 위해 **한 번 연결을 맺으면 끊지 않고 계속 유지**할 수 있도록 개선되었다. (persist connection)
- 또한, 1.0 버전에서는 요청에 대한 응답이 와야 다음 요청을 보낼 수 있었다. 이렇게 되면 응답이 오지 않으면 다음 요청을 할 수가 없다.
- 1.1 버전에서는 응답과 상관없이 **여러 개의 요청**을 보낼 수 있도록 개선했다. (Pipelining)

## HTTP/2

- 1.1 버전에서는 **요청이 순서대로 처리**되기 때문에, 앞의 요청에 대한 응답이 오지 않으면 그 다음 요청에 대한 응답이 와도 처리가 되지 않고 지연됐다.
- 2 버전에서는 **모든 요청과 응답을 병렬적으로 처리**해서 요청에 대한 응답을 대기하지 않고 먼저 도착한 응답을 받을 수 있도록 개선했다.
- 또한, 한 번의 요청으로 여러 개의 응답을 받을 수 있고, 클라이언트가 요청하지 않아도 필요한 리소스를 푸시하는 등 성능과 속도가 많이 개선됐다.

> **바이너리 프레이밍**
> 
> - HTTP/2가 위에서 서술한 기능을 가능케 한 기능이다.
> - HTTP 메시지를 바이너리 형태로 캡슐화하는 기능이다.

## HTTP/3

- 2 버전은 오래된 프로토콜인 TCP 위에서 동작하고 있다.
- TCP는 연결을 확인하는 등 데이터통신 과정에서 여러 작업을 수행하기 때문에 속도가 느리다.
- 3 버전에서는 TCP가 아닌 **UDP**을 사용해서 속도 개선했다.
