## 메모리

**정의**

메모리는 각자 주소를 가진 바이트들의 큰 배열이다. CPU는 프로그램 카운터를 이용해 메모리에서 명령어를 fetch하고, 명령어는 메모리로의 load/store를 유발한다.

**메모리 공간 분리와 보호**

메모리 공간은 사진과 같이 구성되어 있으며, Base Register과 Limit Register으로 각 프로세스마다 별도의 메모리 공간을 보장해야 한다.

- Base Register : 프로세스가 사용 가능한 메모리 영역의 시작 주소
- Limit Register : 프로세스가 사용 가능한 메로리 영역의 크기

![image.png](/assets/images/memory-1.png)

CPU는 유저 모드에서 생성되는 모든 주소를 두 레지스터와 비교하고, 모두 참일 경우 메모리에 접근한다.

![image.png](/assets/images/memory-2.png)

**주소 바인딩**

프로그램은 디스크에 실행가능한 이진 파일 형태로 저장된다. 이를 실행하기 위해서 메모리로 가져와진다. 소스 코드에는 보통 Symbolic 주소를 가지고 있다. 소스 코드를 컴파일러가 컴파일하여 오브젝트 파일로 변환을 할 때, Symbolic 주소가 relocatable 주소로 변환된다. 이후 링커 혹은 로더가 relocatable 주소를 absolute 주소로 변환한다.

- Symbolic Address : 프로그래머가 소스 코드에서 사용하는 이름으로 된 주소
    
    ```c
    int count = 0;        // 'count' 라는 심볼
    
    void main() {         // 'main' 이라는 심볼
        count = count + 1;
        printf("%d", count);   // 'printf' 라는 심볼
    }
    ```
    
- Relocatable Address : 이 모듈의 시작점으로부터 N 바이트 떨어진 위치 형태의 상대 주소
    
    ```
    모듈 내부 오프셋  심볼      크기
       +0           main      120 bytes
       +120         count     4 bytes
       +124         buffer    256 bytes
    ```
    
- Absolute Address : 링커 혹은 로더가 Relocatable 주소를 실제 메모리 위치로 확정한 주소
    
    - 링커 혹은 로더가 위 모듈을 주소 74000번지로 적재하기로 결정했다면 아래와 같이 메모리 위치가 확정된다.
    
    ```
    이전 (relocatable)  →   이후 (absolute)
       +0                    74000  (main)
       +120                  74120  (count)
       +124                  74124  (buffer)
    ```

**논리 주소 vs 물리 주소**

- 논리 주소 공간 : 한 프로세스가 사용할 수 있는 논리 주소들의 공간
    - 논리 주소 : CPU가 생성하는 주소, 프로그램이 보는 주소
- 물리 주소 공간 : 시스템이 실제로 존재하는 물리 주소들의 집합
    - 물리 주소 : 실제 메모리의 하드웨어 주소, 메모리 칩에 전달되는 주소

**MMU**

Memory Managment Unit의 약어로 논리 주소를 물리 주소로 변환을 수행하는 하드웨어 장치이다.

![image.png](/assets/images/memory-4.png)

## 연속 메모리 할당

제한된 크기를 가진 메모리를 여러 프로세스에 대해 효율적으로 할당할 수 있는 방법이 무엇일까? 일반적으로 메모리는 두 파티션으로 나뉘게 된다.

- OS 영역
- 사용자 프로세스 영역

여러 사용자 프로세스가 동시에 메모리에 상주할 수 있어야 하기 때문에, 대기 중인 프로세스에게 어떻게 메모리를 할당해야할지가 문제이다. 이러한 문제를 해결할 수 있는 방법 중 하나가 연속 메모리 할당이다.

연속 메모리 할당은 각 프로세스는 하나의 연속된 메모리 구간에 통째로 들어가고, 그다음 프로세스는 바로 이어지는 다른 연속 구간에 들어가는 것이다. 프로세스가 다음 프로세스 뒤에 위치해야하기 때문에 주소 공간 침범을 막아야하고, Relocation Register과 Limit Register 두 레지스터를 활용하여 메모리 공간 보호를 수행한다. 또한, 변환 로직도 동시에 수행한다.

![image.png](/assets/images/memory-5.png)

### Variable-Partition

메모리를 가변 크기 파티션으로 나누어, 각 파티션에 정확히 하나의 프로세스를 할당하는 방식이다. 사진 처럼 메모리 공간을 가변 크기 파티션으로 나누고 각 공간에 프로세스를 적재한다. 시간이 지남에 따라 프로세스가 종료되면 메모리에는 공간이 생기고 이 공간을 hole이라고 한다. 다음에 실행될 프로세스는 운영체제가 해당 프로세스를 적재할 수 있는 hole를 찾아 할당해준다.

![image.png](/assets/images/memory-6.png)

### Dynamic Storage Allocation Problem

프로세스의 크기는 제각각이고, hole 크기 또한 제각각이다. 이 과정에서 적절한 크기의 hole를 찾은 과정에서 대표적인 세 가지 알고리즘이 사용된다.

- First-Fit : 충분히 큰 첫 번째 hole에 할당
- Best-Fit : 충분히 가장 작은 hole에 할당
- Worst-Fit : 가장 큰 hole에 할당

### 단편화

메모리를 할당하고 해제하는 과정이 반복되면서 메모리 공간이 조각나 총 공간은 충분해도 실제로 사용할 수 없게 되는 현상이다.

**내부 단편화**

- 프로세스의 크기보다 메모리 공간이 큰 경우에 발생
- 일정 크기로 분할 된 메모리 공간에 프로세스가 적재되었지만 여유 공간이 발생
- 하나의 메모리 공간에는 하나의 프로세스만 적재될 수 있기 때문에 사용되지 못함

**외부 단편화**

- 프로세스의 크키가 메모리 공간보다 큰 경우에 발생
- 프로세스가 종료되고 생긴 메모리 사이의 빈 공간에 새로운 프로세스를 적재하지 못함

**해결 방법**

- 통합 기법 : 인접해 있는 두 공간이 비어있다면 하나로 통합
- 압축 기법 : 비어있는 공간들을 통합하여 하나의 공간으로 만드는 작업
- 재배치 기법 : 프로그램의 주소를 새롭게 지정

## 페이징

연속 메모리 할당은 다음과 같은 한계가 존재한다.

- 외부 단편화 : 시간이 지나면 메모리가 작은 hole들로 쪼개진다.
- 압축 비용 : 단편화의 해결 방법으로 비어있는 공간들을 압축할 수 있지만 비굥이 발생한다.
- 연속성 제약 : 프로세스가 반드시 한 덩어리여야 한다.

페이징은 프로세스가 반드시 연속될 필요는 없다라는 아이디어를 통해 연속 메모리 할당의 한계를 해결한다.

페이징의 기본 메커니즘은 Page와 Frame이다.

- Page : 논리 메모리 공간에서 같은 크기 블록으로 나눔
- Frame : 물리 메모리 공간에서 고정 크기 블록으로 나눔

이를 통해 논리 주소 공간과 물리 주소 공간이 완전히 분리된다.

CPU가 생성하는 주소는 두 파트로 분리된다.

- Page Number : 페이지 테이블의 인덱스로 사용
- Page Offset : 해당 페이지 내에서 몇 번째 바이트인지 사용
