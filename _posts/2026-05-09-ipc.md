## IPC

![image.png](/assets/images/IPC.png)

프로세스는 메모리 공간에서 독립적으로 실행된다. 그렇기 때문에, 서로 다른 프로세스 영역에 접근하지 못한다. 하지만, 프로세스를 실행하는 과정에서 다른 프로세스와 통신이 필요하다면 어떻게 해야할까? 그리고 다른 프로세스와 통신이 필요한 상황은 언제일까? 그 상황은 아래와 같다.

- 정보 공유 : 여러 응용 프로그램이 동일한 정보가 필요할 수 있다.
- 계산 가속화 : 특정 작업을 빨리 실행하고자 한다면, 서브 작업으로 나누어 병렬로 실행해야 한다.
- 모듈성 : 시스템 기능을 별도의 프로세스들 또는 스레드들로 나누어 모듈식 형태로 시스템을 구성한다.

프로세스 간 통신, 즉 IPC(Interprocess Communication) 기법은 공유 메모리와 메시지 전달 모델이 있다.

### 공유 메모리

공유 메모리는 메모리 공간 상에 특정 메모리 공간을 두 개이상의 프로세스가 접근하여 데이터를 읽고 쓰고 정보를 교환한다. 위에서 언급한 것 처럼, 프로세스는 다른 프로세스 영역을 침범할 수 없다. 단, 공유 메모리를 사용할 프로세스들이 이 제약 조건을 제거하는 것에 동의한다면 사용할 수 있다.

공유 메모리 모델을 생산자-소비자 시점으로 바라본다면, 공유 메모리에 데이터를 적재하는 생산자와 적재된 데이터를 소비하는 소비자가 존재할 것이다. 이때, 데이터를 쌓는 공간 버퍼는 두 가지 유형이 있다.

- 무한 버퍼 : 생산자는 항상 데이터를 적재할 수 있다.
- 유한 버퍼 : 버퍼 크기가 꽉 찰 경우, 모두 소비될 때까지 생산자는 대기해야한다.

두 개 이상의 프로세스가 동일한 메모리 영역을 접근하기 때문에, 충돌이 발생하지 않도록 신경써야 한다.

### 메시지 전달

하나의 프로세스가 메시지를 전달하는 시스템 콜을 호출하고, 메시지를 받는 프로세스에서 시스템 콜을 호출하면 메시지가 전달되는 방식이다. 해당 과정에서 시스템 콜을 호출하기 때문에 커널을 찍고 온다는 점이 있어, 공유 메모리에 비해 느리다. 다만, 충돌을 회피할 필요가 없기 때문에 적은 양의 데이터를 교환하는 데 유용하다.

두 프로세스가 통신을 원한다면, 통신 연결이 설정되어야 한다.

- 직접 통신
    
    - 통신을 원하는 각 프로세스는 통신의 수신자 또는 송신자의 이름을 명시한다.
    
    ```bash
    send(P, message) - 프로세스 P에게 메시지를 전송
    receive(Q, message) - 프로세스 Q로부터 메시지를 수신
    ```
    
    - 변형으로 송신자만 이름을 명시할 수 있다.
    
    ```bash
    send(P, message) - 메시지를 프로세스 P에 전송한다.
    receive(id, message) - 임의의 프로세스로부터 메시지를 수신한다. 변수 id는 통신을 발생시킨 프로세스의 이름으로 설정된다.
    ```
    
    - 프로세스의 이름을 바꾸면 모든 부분에 수정이 필요하다.
- 간접 통신
    
    - 메일박스 또는 포트로 메시지가 송신되고, 그것으로부터 수신된다.
        
        - 메일박스는 추상적으로 프로세스들에 의해 메시지가 넣어지고, 메시지들이 제거될 수 있는 객체이다.
        - 각 메일박스는 고유의 id를 가진다.
        
        ```bash
        send(A, message) - 메시지를 메일박스 A로 송신한다.
        receive(A, message) - 메시지를 메일박스 A로부터 수신한다.
        ```
        

## 동기화

메시지 전달은 동기형과 비동기형 방식으로 전달된다.

- 동기형 보내기 : 송신하는 프로세스는 메시지가 수신 프로세스 또는 메일박스에 의해 수신될 때까지 블로킹된다.
- 비동기형 보내기 : 손신하는 프로세스가 메시지를 보내고 작업을 재시작한다.
- 동기형 받기 : 메시지가 이용 가능할 때까지 수신 프로세스가 봉쇄된다.
- 비동기형 받기 : 송신하는 프로세스가 유효한 메시지 또는 널을 받는다.

## 파이프

두 프로세스가 통신할 수 있게 하는 전달자로서 동작한다. 파이프를 구현하기 위해서는 다음 4가지 문제를 고려해야 한다.

- 파이프는 단방향 or 양방향
- 양방향 통신이 된다면 반이중 방식 or 전이중 방식
- 두 프로세스 간에 부모-자식 관계가 존재?
- 네트워크를 통하여 통신이 가능한가

파이프에는 두 가지 유형이 존재한다.

- 일반 파이프
    
    ![image.png](/assets/images/Normal-Pipe.png)
    
    - 생산자-소비자 형태로 두 프로세스 간의 통신을 허용
    - 생산자는 파이프의 한 종단에서 쓰고, 소비자는 다른 종단에서 읽는다.
    - 단방향 통신만 가능하며, 양방향 통신을 하기 위해서는 파이프를 두 개 사용해야한다.
    - 파이프를 생성한 프로세스 이외에는 접근할 수 없다.
    - 그렇기 때문에, 부모 프로세스가 자식 프로세스를 만들고 통신하기 위해 사용한다.
- 지명 파이프
    
    - 통신은 양방향으로 가능하며 부모-자식 관계도 필요하지 않는다.
    - 여러 프로세스들이 이를 사용하여 통신할 수 있다.
    - 반이중 전송만 가능하다.

## 소켓

![image.png](/assets/images/Socket.png)

통신의 극점을 뜻하며, 두 프로세스가 네트워크상에서 통신을 하려면 양 프로세스마다 하나씩 총 두 개의 소켓이 필요하다. 각 소켓은 IP주소와 포트 번호를 접합해서 구별한다.

## RPC

네트워크에 연결된 두 시스템 사이의 통신에 사용하기 위하여 프로시저 호출 기법을 추상화하는 방법으로 설계되었다. 프로세스들이 서로 다른 시스템 위에서 돌아가기 때문에 원격 서비스를 제공하기 위해서는 메시지 기반 통신을 해야한다.
