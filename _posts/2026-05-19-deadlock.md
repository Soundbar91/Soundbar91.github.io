## 교착 상태

각 프로세스가 다른 프로세스가 사용중인 자원을 기다리면서, 동시에 해당 프로세스가 사용중인 자원을 다른 프로세스가 요청하여 아무도 진행하지 못하고 영원히 기다리는 상태이다.

### **교착 상태 발생 필요충분조건**

- 상호 배제 : 최소한 하나의 자원이 비공유 모드로 사용되어야 하며, 한 번에 하나의 프로세스만이 그 자원을 사용할 수 있음
- 점유 대기 : 프로세스가 최소한 하나의 자원을 점유하면서 다른 프로세스에 의해 점유된 추가 자원을 대기하는 상태
- 비선점 : 자원이 프로세스에 할당된 후에는 그 프로세스가 자발적으로만 자원을 방출할 수 있으며, 다른 프로세스에 의해 강제로 방출될 수 없음
- 순환 대기 : 대기 중인 프로세스의 집합에서 자원의 대기하는 순환 형태의 대기가 발생

### **해결 방법**

- 예방
    - 교착 상태 발생의 4가지 필요충분조건 중 하나 이상을 무효화
        - 상호 배제 조건 부정 : 실질적으로 불가능 경우가 많으나, 가능한 경우에는 자원 공유를 통해 해결
        - 점유와 대기 조건 부정 : 프로세스가 자원을 요청할 때, 자원을 보유하지 않은 상태에서만 요청할 수 있음
        - 비선점 조건 부정 : 이미 할당된 자원을 프로세스가 사용 중일 때 다른 프로세스의 요청에 의해 회수
        - 순환 대기 조건 부정 : 모든 자원 유형에 대해 선서를 정하고, 프로세스가 순서대로 자원을 요청
- 회피
    - 시스템이 교착 상태에 빠지지 않도록 보장하는 동적인 전략
        - 은행원 알고리즘, 자원 할당 그래프 알고리즘
- 탐지
    - 주기적으로 또는 특정 조건 하에서 시스템을 검사하여 교착상태의 존재여부를 확인하는 과정
        - 자원 할당 그래프 : 프로세스와 자원 유형을 노드, 엣지로는 프로세스가 자원을 요청하거나 자원이 프로세스에 할당되는 관계 표현
        - 사이클 감지 : 그래프 내에 사이클이 존재하는 경우, 시스템에 교착상태가 발생할 수 있음
- 회복
    - 교착상태를 탐지한 후에 시스템을 다시 복구
        - 프로세스 종료 : 교착상태에 관련된 프로세스 중 하나 또는 그 이상을 종료
        - 자원 선점 : 하나 이상의 프로세스로부터 자원을 강제로 회수
