## GIT
### 정의

- 분산 버전 관리 시스템으로, 파일의 버전을 관리할 수 있는 수단이다.
- 이를 통해 파일의 변경사하을 추적하고 여러명의 사용자들 간에 파일에 대한 작업을 조용하는데 사용된다.

### 장점

- Git을 사용하면 손 쉽게 돌아가고 싶은 버전으로 돌아갈 수 있다.
- 협업 과정에서 다른 개발자들의 코드 이력을 쉽게 확인할 수 있다.
- 또한, 별도의 제약 없이 여러 사람이 같은 파일을 동시에 작업할 수 있다.

### 용어

- 리포지토리
    - 소스 코드, 파일, 디렉토리 등의 버전 관리를 위해 사용되는 저장소이다.

- 로컬
    - 사용자의 현재 컴퓨터에 저장된 리포지토리이다.
- 리모트
    - 원격 서버나 클라우드에 저장된 리포지토리이다.
    - 로컬 리포지토리와 동기화할 수 있다.
- 브랜치
    - 프로젝트의 특정 시점에서 분기된 독립적인 작업 공간이다.
    - 여러 브랜치를 만들어 다양한 기능이나 버그 수정을 동시에 진행할 수 있다.
- 커밋
    - 커밋하기 전에 변경된 파일을 임시로 저장하는 영역이다.
    - 스테이징 영역에 추가된 파일만 커밋에 포함된다.
- 스테이징
    - 커밋 하기 전 파일을 보관하는 영역이다.
- 푸시
    - 로컬 리포지토리의 변경 사항을 원격 리포지토리에 업로드하는 행위이다.
- 풀
    - 원격 리포지토리의 변경사항을 로컬 리포지토리에 가져오고 자동으로 병합하는 행위이다.
- 페치
    - 원격 리포지토리의 변경 사항을 확인만 한다.
    - 병합은 별도로 수행해야 한다.

## GitHub

- Git을 기반으로 소스 코드와 관련 파일을 저장하고 관리할 수 있는 웹 기반 호스팅 서비스를 제공하는 플랫폼이다.
- 버전 관리 기능 외에도 이슈 트래킹, 코드 리뷰 등의 기능을 제공하여 개발자들이 효과적으로 협업할 수 있게 한다.

## 자주 사용했던 명령어

- git init : `.git` 파일을 생성하는 명령어이다.

- git clone : 원격 리포지토리의 내용을 로컬 리포지토리에 복제하는 명령어이다.
- git checkout : 특정 브랜치로 이동하는 명령어이다.
- git status : 현재 브랜치에서 변경 사항이 있는 파일들을 보여주는 명령어이다.
    - Untracked 상태 : git이 추적하지 않는 상태, Untracked files에 빨간색으로 표시
    - Staged 상태 : Staging Area에 있는 상태, Changes to be committed에 초록색으로 표시
    - Modified 상태 : 파일에 변경사항이 있는 상태, Changes not staged for commit에 빨간색으로 표시
- git add : Modified 상태의 파일을 스테이징 영역에 올리는 명령어이다.
- git commit : 커밋을 수행하는 명령어이다.
- git push : 푸시를 수행하는 명령어이다.
- git fetch : 페치를 수행하는 명령어이다.
- git pull : 풀을 수행하는 명령어이다.

## 마무리
요즘은 IDE에서 제공해주는 GIT GUI(?) 같은 걸로 편하게 하기 때문에 명령어는 잘 사용하고 있지 않은 것 같다. 하지만 모든 것이 그러듯 기본이 중요하다. 
IDE에서 제공해주는 것만으로도 해결이 안되는 것이 존재할 수 있기 때문에 기회가 된다면 명령어도 자주 사용해보는 것이 좋겠다고 생각이 들었다. 
또한, 좀 있으면 회고 프로젝트를 진행하는데 Git Workflow도 한 번 학습하고 적용해보면 좋겠다는 생각이 들었다.
