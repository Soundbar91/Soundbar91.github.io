# OSI 7 Layer

![](/assets/images/velog/c635b37a-22e8-48de-82ae-5d791ebdc8c1-image.png)

## 정의

- 네트워크 프로토콜 디자인과 통신 과정을 **7개의 계층**으로 구분하여 만든 **표준 규격**이다.
- 계층 구조로 구성되어 있기 때문에 상위 계층이 제대로 동작하기 위해서는 하위의 모든 계층에 문제가 없어야 한다.
- 또한, 각 계층은 **독립**적인 모듈로 구성되어 있다.

## 필요성

- 표준 규격이기 때문에 서로 다른 통신 장치와 **상호 호환**이 가능하다.
- 각 계층은 독립적이기 때문에 특정 단계에 이상이 생기면 해당 단계만 고치면 되므로 **유지보수**가 좋다.
- **설계가 간단**해지고, **통신의 흐름**을 알아보기 쉽다.

## 계층 별 설명

- 1계층 (물리 계층)
    - 상위 계층에서 전송된 데이터를 라우터, 케이블 등 물리적인 전송 매체를 통해 **다른 시스템에 전기적 신호를 전송하는 역할**
    - 데이터를 **전달**하는 역할만 한다.
    - PDU : **비트**
    - 프로토콜 : Modem, Cable, RS-232C
- 2계층 (데이터 링크 계층)
    - 네트워크 계층에서 받은 **데이터를 물리 계층으로 전송**하는 역할을 한다.
    - 물리 계층을 통해 송수신되는 **데이터의 오류를 제어**한다.
    - 네트워크 계층에서 받은 데이터에 주소와 제어 정보를 헤더와 테일에 추가한다.
    - MAC 주소를 가지고 통신을 한다.
    - PDU : **프레임**
    - 장비 : 브리지, 스위치
    - 프로토콜 : 이더넷, MAC, LAN, Wifi
- 3계층 (네트워크 계층)
    - **목적지의 IP와 경로**를 선택하고, 패킷을 전달해 주는 역할을 한다.
    - 여러 개의 노드를 거칠 때마다 경로를 찾아주는 역할을 한다.
    - 데이터를 목적지까지 **안전하고 빠르게 전달**하는 것이 가장 중요하다.
    - PDU : **패킷**
    - 장비 : 라우터, L3 스위치
    - 프로토콜 : IP, ICMP, ARP, RARP
- 4계층 (전송 계층)
    - 패킷의 전송이 **유효**한지 확인하고 유효하지 않은 패킷인 경우 다시 보내는 역할을 한다.
    - 헤더에 **포트 번호**와 **세그먼트**가 포함되어 있다.
    - PDU : **세그먼트**
    - 장비 : 게이트웨이, L4 스위치
    - 프로토콜 : **TCP**, **UDP**
- 5계층 (세션 계층)
    - 네트워크 상 **양쪽 연결을 관리하고 연결을 지속**시켜주는 역할을 한다.
    - **포트 번호를 기반**으로 연결한다.
    - 프로토콜 : SSH, TLS
    
    > 세션 : 서버에 접속한 후, 접속을 종료할 시점까지를 의미
    > 
- 6계층 (표현 계층)
    - 송수신되는 **데이터의 인코딩, 디코딩 그리고 암호화**를 하는 역할을 한다.
    - 프로토콜 : JPG, MPEG, SMB, AFP
- 7계층 (응용 계층)
    - 사용자와 바로 연결되어 있으며, 응용 SW를 도와주는 역할을 한다.
    - 사용자로부터 입력받은 정보를 하위 계층으로 전송하고 하위 계층으로 부터 받은 데이터를 사용자에게 전달한다.
    - 프로토콜 : HTTP, DNS, Telnet 등

> PDU : 각 계층에서 전송되는 단위
> 

# NAT

![](/assets/images/velog/705020a0-5eb1-4e0b-9277-a020c4431aa8-image.png)

## 정의

- **사설 IP를 공인 IP로 변경**하는 주소 변환 서비스이다.
- 학교와 회사와 같은 단체에서 사용되는 사설 IP가 외부 인터넷에 연결 시엔 하나의 공인 IP로 변환한다.

## 원리

- 192.168.1.1에서 외부 68.1.31.1로 접근을 하기 위해 라우터에 요청을 보낸다.
- 라우터는 요청을 보낸 192.168.1.1를 기록하고, 요청 IP를 확인한다.
- 요청 IP는 사설 IP이기 때문에 이를 공인 IP로 변환하고 68.1.31.1로 접근한다.
- 68.1.31.1에서는 접근에 대한 응답을 라우터에 보낸다.
- 라우터는 받은 응답을 사설 IP 192.168.1.1로 보낸다.

## 필요성

- **IP 주소를 절약**할 수 있다.
    - IP주소는 한정돼 있기 때문에 단체에서 사용되는 컴퓨터가 공인 IP를 사용하게 되면 IPv4는 이미 고갈 됐다.
    - 이를 절약하기 위해 단체에 하나의 공인 IP를 부여해서 IP 주소를 절약할 수 있다.
- 내부로의 **해킹이나 침입을 막을 수 있다**.
    - 단체 내부에서 사용되는 PC마다 사용하는 IP 주소와 포트 번호가 다르다.
    - 하지만 외부에서 보면 단체에서 사용하는 IP는 공인 IP로 동일하다.
    - 이를 통해 단체 내부의 PC에 직접적으로 접근을 할 수 없다.

> 사설 IP 대역
10.0.0.0 ~ 10.255.255.255
172.16.0.0 ~ 172.31.255.255
192.168.0.0 ~ 192.168.255.255
> 

# IP

![](/assets/images/velog/2c932562-e0da-4206-9eb7-efac473af582-image.png)

## 정의

- 데이터를 **목적지까지 전달하는 기능**을 수행하고 동시에 **주소를 관리**하는 기능을 수행한다.
- **3계층**인 네트워크 계층에 해당하며, **호스트의 주소지정**과 **패킷 분할 및 조립** 기능을 담당한다.
- IP 정보는 4계층에서 받은 데이터에 header 형태로 붙여준다.

## 포멧

- Version : IPv4인지 IPv6인지 구별
- Header Length : 헤더의 길이 (Options를 제외한 5줄, 총 20byts가 기본적인 헤더의 길이이다)
- Total Length : 데이터의 총 길이이다.
- Identification, Flags, Fragment Offset : 단편화와 재결합을 위해 사용되는 값이다.
- TTL (Time To Live) : 데이터가 넘어갈 수 있는 라우터의 개수이다. 라우터를 1개씩 건너갈 때마다 TTL은 1씩 줄어든다. TTL이 0이 된 경우 데이터가 삭제된다. 데이터가 목적지에 도달하지 못했을 경우, 네트워크에 데이터가 남아있는 것을 방지하기 위해 사용한다.
- Header Checksum : 데이터의 에러 검출을 위해 사용하는 값이다.
- Source IP Address : 데이터의 출발 IP이다.
- Destination IP Address : 데이터의 목적 IP이다.
- data : 전송 데이터이다.

## 단편화와 재결합

- 단편화 (fragmentation)
    - 네트워크에 연결된 장치가 받아들일 수 있는 **최대 데이터 패킷 크기**가 있다. 이를 MTU(Maximum Transmission Unit) 사이즈라고 한다.
    - MUT는 네트워크 링크마다 값이 다르다.
    - 데이터를 전송할 때, 데이터의 크기가 네트워크의 MTU 사이즈보다 **작은 경우 데이터를 쪼개서 보내야 한다**.
    - 이를 단편화라고 한다.
- 재결합
    - 단편화된 데이터를 도착지에서 다시 합시는 것을 재결합이라 한다.
    - Identification, Flags, Fragment Offset를 참고하여 데이터를 재결합한다.

## IPv4

- 32bit로 구성되어있으며 한 칸당 10진수 8bit의 총 4조각으로 구성된다.

## IPv6

- 128bit로 구성되어있으며, 한 칸당 16bit를 4라지의 16진수로 표현하여 8조각으로 구성된다.
- 표현할 수 있는 주소가 엄청나게 많다.

## 한계점

- 비연결성 : 받을 대상이 없거나 받을 수 없는 상태에도 전송한다.
- 비신뢰성 : 데이터가 정확하게 갔는지 확인하지 않는다.

# DNS

![](/assets/images/velog/a304ede1-db53-43f5-9085-29faa0a3f016-image.png)

## 정의

- 네트워크 주소를 사람이 기억하기 쉽고 알수 있는 이름으로 변경하는 시스템이다.

## 동작 원리

- 클라이언트에서 google.com에 접속을 시도한다.
- 접속을 시도할 때, DNS 서버에 접속하려는 도메인 주소를 전달한다.
- DNS 서버는 도메인 주소에 해당하는 네트워크 주소를 클라이언트에 전달한다.
- 클라이언트는 DNS 서버로부터 받은 네트워크 주소를 이용해서 서버에 접속한다.
